# Calutron
Calutron — платформа A/B-экспериментов. Calutron помогает продуктовым командам пройти путь от гипотезы и подготовки аудитории до сравнения вариантов и фиксации решения. Платформа объединяет online- и offline-эксперименты, сплитование со стратификацией, донабор по расписанию, A/B-флаги (тоглы) и работу через AI-ассистентов.

## Возможности платформы

| Задача | Возможности Calutron |
|---|---|
| Подготовить эксперимент | Контрольная и тестовые группы, сроки, основная, информационная и барьерная метрики, копирование дизайна |
| Оценить выборку | Расчёт размера выборки и MDE, предварительная оценка доступной аудитории |
| Определить аудиторию | Бизнес-фильтры, списки из файлов, условия участия на основе групп других экспериментов |
| Распределить участников | Абсолютные размеры или относительные доли групп, online-назначения, offline-стратификация |
| Управлять набором | Контроль пересечений, проверка первичной разметки, повторный запуск и донабор по расписанию |
| Выдавать варианты продукта | Значения A/B-тоглов для групп и управление их дальнейшей выдачей после выбора победителя |
| Подвести итоги | Метрики групп, статистические сравнения, ссылка на анализ и фиксация решения с победителем или без него |
| Организовать работу команды | Роли и права, история состояний, аудит разметки и напоминания |
| Подключить AI-ассистента | Поиск и создание экспериментов, оценка аудитории, расчёты и подготовка аналитических запросов через MCP |

## Сплитование и управляемый набор

**Online-тест** набирает участников по мере обращения к продукту, с учётом доли трафика, условий участия и пересечений. **Offline-тест** формирует группы заранее и позволяет проверить результат перед подтверждением.

В offline-сценарии можно стратифицировать аудиторию по бизнес-признакам либо участию в других экспериментах. Первичную разметку можно пересмотреть и выполнить заново. Для действующего теста доступен донабор новых подходящих клиентов по расписанию с сохранением существующих назначений.

[Сплитование, стратификация и повторная разметка →](docs/splitting.md)

## От проведения теста к продуктовому решению

Состояния теста, разметки и тоглов связаны правилами переходов — Rule Policy. Можно завершить набор и продолжить период наблюдения, затем перейти к анализу и определить дальнейшее поведение вариантов продукта. Права пользователя проверяются отдельно (Role Policy).

Команда изучает рассчитанные метрики и статистические сравнения, сохраняет выводы и фиксирует итог. Выбор победителя остаётся явным решением команды.

[Жизненные циклы тестов, разметок и тоглов →](docs/lifecycle.md)

## Для разработчиков и технических партнёров

Платформа разделена на управление экспериментами, online-разметку, выдачу тоглов, offline-worker, расчёт результатов и MCP-адаптер. Для взаимодействия используются REST API, HTTP-выдача тоглов, MCP и обмен данными с аналитической средой.

[Технический обзор](docs/technical-overview.md) содержит диаграмму, описание шести компонентов платформы, стек, пример MCP-вызова, механизмы доступа и наблюдаемости, а также инфраструктурные зависимости.

## Для каких команд

- **Продуктовым командам** — проверять изменения интерфейсов и предложений, управлять набором и сохранять решения.
- **Аналитикам** — планировать выборку, настраивать распределение и метрики, сравнивать группы.
- **Разработчикам и партнёрам** — связывать поведение продукта с экспериментами и подключать внутренние инструменты или AI-ассистентов.

Платформа предусматривает сценарии для авторизованных пользователей, анонимной аудитории и сотрудников. Состав возможностей зависит от выбранного сценария.
